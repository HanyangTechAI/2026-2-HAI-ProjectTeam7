### split_manifest.csv

manifest의 **동일한 7개 컬럼**에 아래 컬럼이 추가되어 있습니다. video_id별 7개 값이 manifest와 일치하며 180,000개 영상이 중복 없이 연결됩니다.

| 추가된 실제 컬럼 | 의미 |
|---|---|
| split | `train`, `val`, `test` |

Train 130,000행/13명, val 30,000행/3명, test 20,000행/2명입니다. 각 split의 content_id는 같은 2,000종입니다. 수연자 교집합과 `(signer_id, content_id)` 그룹 교집합은 0입니다. 촬영 각도 코드는 U 36,008행, D/F/L/R 각 35,998행입니다. 36,000개 수연자·문장 그룹 중 35,998개는 D/F/L/R/U 각 1행이며 2개 그룹 `(REAL11, SEN1085)`, `(REAL14, SEN1573)`은 5행 모두 U입니다. 실제 영상의 촬영 각도 또는 CSV 파싱·작성 규칙을 확인해야 합니다. 실제 수행 ID 필드는 없으므로 원본의 중복·재촬영까지 검증한 것은 아닙니다.

## 확인한 형태소 JSON과 미확인 키포인트 JSON

`p0_verified_samples/`의 JSON 5개는 `NIA_SL_SEN0002_REAL17`의 D/F/L/R/U 형태소 주석입니다. 모두 다음 키를 가집니다.

| 실제 키 경로 | 의미 |
|---|---|
| metaData.url | 원본 영상 URL 문자열. 이번 작업에서 접속·권한 검증하지 않음 |
| metaData.name | 영상 파일명 |
| metaData.duration | 영상 길이 메타데이터 |
| metaData.exportedOn | 내보내기 일자 문자열 |
| data[].start / end | 형태소 구간 시작·종료 시각 |
| data[].attributes[].name | Gloss 표기 |
| data[].attributes[].attribute | 비수지 속성 배열 |

이 5개로 전체 주석 구조·완전성을 보장하지 않습니다. 원본 키포인트 JSON은 로컬 폴더에서 발견되지 않았으므로 파싱 결과를 만들지 않았습니다. 요청에서 제시된 명세상 왼손 21·오른손 21·Pose 25·Face 70 = 137개, x/y/confidence는 **명세 기준의 검증 대상**입니다. 실제 JSON 키, 관절 순서, 채널 수·단위, confidence 범위, FPS·타임스탬프, 사람 추적 및 결측 표시는 담당자가 확인해야 합니다. MediaPipe의 구성과 동일하다고 가정하지 않습니다.

## 목표 전처리 인터페이스 (미구현 설계안)

```python
{
    "keypoints": ...,     # float32 (T, J, C), 유효 시계열 길이 보존
    "length": ...,        # 정수, Padding 전 T
    "video_id": ...,
    "signer_id": ...,
    "segments": [
        {
            "start_frame": ...,  # 포함
            "end_frame": ...,    # 미포함
            "gloss_id": ...,
            "nms_labels": ...
        }
    ]
}
```

위 키는 새 계약 제안이며 현재 Dataset이 반환하는 값이 아닙니다. 실제 CSV에 `gloss_id`, `nms_labels`, frame 인덱스는 없습니다. Gloss/NMS 매핑은 별도 버전 관리합니다.

1. **파일 연결:** video_id로 CSV·형태소 JSON·실제 키포인트를 연결합니다. keypoint_prefix를 경로라고 단정하지 않고 승인된 root와 프레임 파일 목록을 대조합니다. 미연결은 사유와 함께 보류합니다.
2. **길이 보존:** 실제 프레임 시각·유효 길이를 보존하고 무조건 T=32로 바꾸지 않습니다. 원본 프레임 누락과 재샘플링은 별도 기록합니다.
3. **정규화:** 몸 기준 이동·크기 정규화를 검토하고 Train에서만 통계를 추정합니다. confidence는 좌표처럼 정규화하지 않습니다. 머리 방향·움직임을 지우는 프레임별 얼굴 정렬은 피하거나 별도 특징으로 보존합니다.
4. **입력 선택:** 손·상체가 Manual, 같은 손·상체에 얼굴을 더한 것이 Holistic입니다. Pose 25개에는 상체 외 부위가 있을 수 있어 상체 선택 인덱스와 머리 관련 점의 A/B 중복을 문서화합니다. 관절·채널 목록은 실제 스키마 확인 후 고정합니다.
5. **초→프레임:** 고정 FPS f, 원점이 확인된 경우 `[floor(start_sec*f), ceil(end_sec*f))`를 초기 규칙으로 제안하고 `[0,T]`로 제한합니다. 가변 FPS 또는 원점 차이가 있으면 실제 프레임 시각으로 매핑합니다. FPS=30을 로컬 검증 없이 강제하지 않습니다. 0길이·역전·범위 밖·Gloss 없는 구간은 보류·제외 근거를 남깁니다.
6. **정답 연결:** 구간별 Gloss 정답과 NMS 배열을 연결합니다. 단어 클립 전체 라벨, 형태소 구간 라벨, 문장 전체 순서 라벨을 혼용하지 않습니다.
7. **Annotation Missing:** 빈 `nms_tags=[]`는 그 자체로 검증된 음성이 아닙니다. 주석 완전성을 확인해 `검증 양성 / 검증 음성 / 미확인`을 구분합니다. 추가 `nms_mask`를 구간 또는 태그별로 전달하는 방식을 협의하고, 미확인은 NMS Loss·평가에서 제외합니다. 이는 현재 CSV에 존재하는 컬럼이 아닙니다.
8. **Batch/Padding:** 영상 시퀀스를 보관하되 첫 모델은 유효 정답 구간을 잘라 구간별 분류합니다. collate 단계에서 `(B,T_max,J,C)`, lengths `(B,)`, 시간 마스크를 만들고 segment 목록은 가변 길이로 유지하거나 구간 배치로 변환합니다. Padding이 GRU 최종 상태·pooling·손실에 포함되지 않게 합니다.
9. **분할:** 제공된 split_manifest를 적용하고 새 무작위 프레임·구간 분할을 하지 않습니다. 같은 수연자의 모든 각도·파생 구간은 같은 split에 둡니다. 같은 문장 ID가 분할에 공존하는 현재 조건을 결과에 명시합니다.
10. **산출물:** 원본 영상이 없어도 전처리 Tensor, 시각·length, 구간·정답·mask, split과 매핑만으로 학습할 수 있게 저장합니다. 저장 형식과 버전은 담당자 합의 전이며 생성된 Tensor는 Git에서 제외합니다.
